# Scribe Phase 3 — Mac App Implementation Plan

**Goal:** Replace the Mac placeholder with the real app: a two-column `NavigationSplitView` (glass sidebar + item list with Things-style inline editing), the keyboard model of spec §9.3, search, a window quick-add that follows §19, a `MenuBarExtra` with today's agenda and quick-add, and the ⌃⌥Space Spotlight-style panel. Re-add Mac push registration with logging (spec §18).

**Spec:** §4, §6, §8 (Mac rows), §9.1, §9.3, §9.4, §12, §13, §18, §19. Backlog "Phase 3".

**Architecture:** Pure, tested logic goes to ScribeCore `Presentation/`: the sidebar model (entries, ⌘0–⌘9 mapping, selection after a delete), keyboard command routing, selection after a row leaves the list, `StoreUndo` (store writes registered with Foundation's `UndoManager`, so ⌘Z/⇧⌘Z are the standard Edit menu), today's agenda for the menu bar, and the hotkey panel's placement. The app reuses `ItemEditor` (moved to `App/Shared`, store writes injected instead of read from the iPhone router) and the composer's chip rows (new `App/Shared/QuickAddRows.swift`); everything else Mac-only lives in `App/macOS/`. `KeyboardShortcuts` 3.1 is linked for macOS only.

**Not in this phase:** Settings window contents and the hotkey recorder (Phase 6), widgets/Control/Siri (Phase 4), notifications (Phase 5), the Mac `CKErrorDomain 6` after the dev reset (environmental).

## Global constraints

Same as Phase 2's: Swift 6, macOS/iOS 26, Core imports only Foundation/Observation/SwiftData, no model changes, no `try!`/`fatalError` in app code, zero warnings, `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`, `xcodegen generate` after `project.yml` changes. iPhone behaviour must not change; the 7 iOS UI tests stay green (simulator `DF61C7C2-B064-411D-993E-061AC929BD29`). Branch `phase3-mac`.

## Tasks

1. **Sidebar + command routing (Core, TDD).** `SidebarEntry { upcoming, inbox, category(UUID) }` with `filter`/`categoryID`; `Sidebar.showsInbox(itemCount:selection:)`, `entry(forShortcutDigit:categories:)` (0 → Upcoming, 1–9 → nth category), `validated(_:categories:)`, `selection(afterDeleting:from:)` (next, else previous, else Upcoming). `ListCommands.action(for:in:)` over `ListCommandContext(listIsFocused, isEditingText, selectedItem, categories)`; `ListSelection.afterRemoving(_:from:)`. Tests: `SidebarTests`, `ListCommandsTests`.
2. **StoreUndo (Core, TDD).** `StoreUndo(store:manager:onError:)`: `deleteItem`, `setDone`, `deleteCategory`, `update(_:actionName:_:)`; each registers an undo whose handler re-registers the inverse (redo). Tests drive a real `UndoManager` (`groupsByEvent = false`).
3. **TodayAgenda + PanelPlacement (Core, TDD).**
4. **Shared views.** Move `ItemEditor` to `App/Shared` (inject `perform`; macOS: focus title on open, Esc closes, field-style time picker). Extract the composer chip rows and the row subtitle. iOS build + 7 UI tests.
5. **Mac plumbing.** `KeyboardShortcuts` from 3.1.0 with `destinationFilters: [macOS]`; `LD_RUNPATH_SEARCH_PATHS[sdk=macosx*]`; `ScribeApp` hooks; `MacAppDelegate` (`registerForRemoteNotifications`, delegate callbacks logged to `com.noamchuri.scribe`/`push`, CloudKit events to `sync`, `applicationDidBecomeActive` → refresh).
6. **Main window.** Router, split view, sidebar, item list (Upcoming agenda, category/Inbox sections with collapsed Done, search groups), rows, context menu, keyboard, deep-link drain, `scenePhase` refresh.
7. **Window quick-add** — glass capsule at the bottom of the list; ⌘N focuses it; the selected category is preselected (§19).
8. **Menu bar extra** — window style; quick-add + overdue/today with checkboxes; item click opens it in the main window; opening activates the app.
9. **Hotkey panel** — `KeyboardShortcuts.Name.quickAdd` default ⌃⌥Space; borderless `NSPanel` on the screen under the pointer, `acceptsFirstMouse`, app activation, Esc via keyDown 53, Return saves and closes, resigning key closes; the previously active app gets activation back.
10. **Verify + docs** — Core suite, iOS UI tests, both builds, background-launched screenshots of the Mac window (`-uiTesting -demoData`), README/backlog, report.

## Decisions

- **Keyboard scope.** ⌘N, ⌘F and ⌘0–⌘9 are menu commands that work anywhere in the main window (they never collide with text editing). Space, Return and ⌘⌫ act only when the item list has focus and no text is being edited. ⌘⌫ stays enabled while typing and forwards `deleteToBeginningOfLine:` to the text field — an AppKit disabled menu item with a key equivalent swallows the keystroke (verified with a test harness), which would break ⌘⌫ in text fields. Space is not a menu key equivalent for the same reason. Plain ⌫ (Edit › Delete) also deletes the selected item, like Mail/Reminders.
- **⌘0 = Upcoming**, ⌘1–⌘9 = the first nine categories in sidebar order (spec names only the categories; Upcoming needs a key too). A "Go" menu lists them.
- **⌘Z is the system undo** (`UndoManager` of the window): delete item, delete category, done/not done, and context-menu edits (move, date, kind) are undoable and redoable. Editor text edits rely on the text field's own undo.
- **Rows:** click selects; double-click or Return opens the inline editor; Esc, Return in the title, or selecting another row closes it. After a delete (or a completed task leaving the agenda) the next row is selected.
- **Inbox** shows while it holds items, and also while it is selected so it doesn't vanish under the pointer when its last item is moved out. Deleting the selected category selects its neighbour (then Upcoming).
- **Search** uses the toolbar field (`.searchable`); a non-empty query replaces the list with results grouped by category, across everything including done (§9.2).
- **Quick-add in the window** is a glass field at the bottom of the list (not a sheet or popover — inline-editing taste, §9.1); Return adds and keeps focus for the next entry; a line confirms where it went. In the menu bar and hotkey panel nothing is preselected (no category on screen), so `#tag` or a chip picks it (§19).
- **Menu bar extra** label is an icon only; clicking an item or "Open Scribe" opens the main window (`WindowGroup(id: "main")`) and shows it there via `pendingLink`.
- **Hotkey panel** activates the app (spec §9.3) and hands activation back to the app that was frontmost when it closes, so Esc/Return return the user to where they were. It is not registered in `-uiTesting` runs.
- **Mac push**: registration and callbacks are logged; the CloudKit event log records imports with timestamps so a signed run can tell push-driven imports from activation imports.
- No Settings scene (Phase 6). No macOS UI-test target: driving the Mac UI would take over the author's live keyboard and mouse; screenshots of a background-launched `-uiTesting -demoData` instance are used instead.
